RESEARCH: State Management
Why you are doing it:
To decide how to handle application state efficiently. Small apps can use useState and useContext, but larger apps may benefit from a global state manager like Redux or Zustand.

What you expect to learn/do:

The best cases for using useState, useContext, Redux, or Zustand
When a global state manager is necessary vs. local component state
What do you expect to do with it, including any code you expect to write:

Implement a small test app to compare state management methods
Decide which approach will work best for the app
Implement initial state management setup in the project


-------
Notes:

State managements is the process of how our application will be handling data and its state across the different parts of our application. 

For our react application, there is 4 main approaches
- useState for the small isolated components. 
- useContext for simple across components
- Redux or Zustand for global states and large data handling.

For an app like ours, it's best to use multiple approaches where appropriate.



Ideally,

UseState can be used for ui toggles and form inputs.
- useful to manage simple form inputs like the toggles and switch inputs or buttons
- one component

UseContext will be used for the user settings like dietary preferences or expertise level
- this fits since it's a global state but it doesn't need as many frequent updates as the api

Redux seems to be the better choice over zustand as we will be doing a lot of api calls whether it's to openai or many of the cooking related api's we have. Redux is better able to handle all of those and has better developer tools to support us as well.
- perfect for the api data
- consistent
- handles abundant data well.
