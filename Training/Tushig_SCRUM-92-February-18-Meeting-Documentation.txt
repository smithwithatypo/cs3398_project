February 18 Meeting Documentation

Frontend (React)
Technologies:
✅ React.js - Component-based UI framework
✅ Tailwind CSS - little harder but more customizable and marketable
✅ Axios - For making requests to the backend
✅ React Router - For navigation and routing between pages
✅ State Management Approach:
useState → UI toggles, form inputs
useContext → User settings (e.g., dietary preferences, expertise level)
Redux → Shared global state (API calls, user profile, recommendations) (needs more research)
“Prop drilling” - one main parent that handles all api calls, then sends out the data to childs components (an analogy is like passing parameters into a function).
Methodologies:
Component-based architecture → Reusable and maintainable UI components
State management strategy → Using multiple state management techniques based on use case
Separation of concerns → Backend handles API calls, frontend focuses on UI

Backend (Node.js & Express)
Technologies:
✅ Node.js - JavaScript runtime for handling API logic
✅ Express.js - Lightweight backend framework for handling routes and API calls
✅ Axios - Used in the backend to call external APIs (OpenAI, Spoonacular, etc.)

✅ .env - For storing API keys securely
✅ Cors - For handling cross-origin requests between frontend and backend
		Hard but we will need.
Methodologies:
Backend-for-frontend (BFF) approach → The backend handles all API calls and sends clean data to the frontend
Security best practices → Storing API keys in .env, not exposing them in frontend
Modular architecture → Separate routes/controllers for different API functionalities

Database
Technologies:
✅ MongoDB - NoSQL database for storing user preferences, saved recipes, and interactions.
Methodologies:
Document-based storage → Ideal for flexible data (e.g., recipes, user preferences)
RESTful API design → API endpoints will allow CRUD operations on user data
